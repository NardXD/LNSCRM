API Guide

Connect to ItsWorkPlace CRM with the MCP Data API or the Recorder API.

v1.2.0 OpenAPI 3.1

Overview

ItsWorkPlace CRM exposes two HTTP APIs. Each request is authenticated and scoped to a single company, so data is always isolated to the credentials you are given.

📚
CRM Data API (MCP)

Read and write CRM data — clients, deals, tasks, tickets, invoices, HR, payroll, and knowledge base. JSON-RPC 2.0 over POST /mcp. Auth: X-API-Key.

🎥
Recorder API

Desktop and mobile clients for time tracking and screen-recording uploads. REST JSON at /api/recorder/*. Auth: Bearer token.

Base URL

All endpoints are relative to your CRM host. Production uses per-company subdomains.

EnvironmentURL patternExample
Production (tenant) https://{subdomain}.logon.online https://itsworkplace.logon.online
Production (root) https://logon.online Valid for MCP when using an API key
APIEndpoint prefixCompany scope from
MCP/mcpAPI key (not hostname)
Recorder/api/recorder/*company_subdomain at login
⚠

Always use HTTPS in production. Credentials sent over plain HTTP can be intercepted.

Authentication

The two APIs use different credential types. Use the one that matches the API you are calling.

CRM Data API — X-API-Key

Each company has one or more API keys. A key is generated on the server and shown only once. Send it on every MCP request.

X-API-Key: mcp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Create keys

  • Admin UI: Admin → API Keys (set write access and allowed tools)
  • CLI: php artisan mcp:create-key --company=1 --name="Production" --write

Read-only vs write-enabled keys

Keys are read-only by default and can only call get_* tools. Write access is granted per key at creation time.

⚠

Write tools called with a read-only key return HTTP 200 with isError: true — not HTTP 403. Grant write keys sparingly.

Recorder API — Bearer token

Exchange user credentials via login. Tokens are valid for 30 days and must be sent on every protected request.

Authorization: Bearer rec_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Token expiration & refresh

There is no token refresh endpoint. When a Recorder token expires, call POST /api/recorder/login again to obtain a new token.

Key rotation & revocation

  1. Create a new API key (admin UI or Artisan).
  2. Update your integration to use the new key.
  3. Revoke the old key in Admin → API Keys (delete).

Plaintext keys cannot be retrieved after creation — rotation always means issuing a new key.

Permissions & Scoping

CapabilityRead-only keyWrite key
get_* toolsYesYes
create_* / update_* toolsNo (isError: true)Yes
tools/list, initialize, pingYesYes

Per-tool restrictions

Each key can be limited to a specific set of tools via allowed_tools. When restricted, calling any other tool returns isError: true with a "not permitted" message.

php artisan mcp:create-key --company=1 --tools=get_clients,get_deals

All referenced IDs (client_id, project_id, user_id, etc.) must belong to the same company as the API key.

Environments

Use separate API keys per environment. Never use production keys in staging, CI logs, or non-production systems.

EnvironmentRecommendation
ProductionRead-only key unless writes required; restrict allowed_tools
StagingDedicated company + dedicated keys

  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": process.env.MCP_API_KEY,
  },
  body: JSON.stringify({
    jsonrpc: "2.0",
    id: 3,
    method: "tools/call",
    params: { name: "get_clients", arguments: { status: "active" } },
  }),
});

const envelope = await res.json();
if (envelope.error) throw new Error(envelope.error.message);
if (envelope.result?.isError) {
  const err = JSON.parse(envelope.result.content[0].text);
  throw new Error(err.error ?? "Tool error");
}

const data = JSON.parse(envelope.result.content[0].text);
console.log(data.clients);
$response = Http::withHeaders(['X-API-Key' => env('MCP_API_KEY')])
    ->post('{{BASE_URL}}/mcp', [

        'id' => 3,
        'method' => 'tools/call',
        'params' => ['name' => 'get_clients', 'arguments' => ['status' => 'active']],
    ])
    ->json();

if (isset($response['error'])) {
    throw new RuntimeException($response['error']['message']);
}

$text = $response['result']['content'][0]['text'];
$payload = json_decode($text, true);

if ($response['result']['isError'] ?? false) {
    throw new RuntimeException($payload['error'] ?? 'Tool error');
}

$clients = $payload['clients'];
import os, json, requests

r = requests.post(
    "{{BASE_URL}}/mcp",
    headers={"X-API-Key": os.environ["MCP_API_KEY"]},
    json={
        "jsonrpc": "2.0",
        "id": 3,
        "method": "tools/call",
        "params": {"name": "get_clients", "arguments": {"status": "active"}},
    },
)
envelope = r.json()
if "error" in envelope:
    raise RuntimeError(envelope["error"]["message"])
result = envelope["result"]
payload = json.loads(result["content"][0]["text"])
if result.get("isError"):

print(payload["clients"])

Quick Start — Recorder API

Login, clock in, and check status.

# 1. Login
curl -X POST "{{BASE_URL}}/api/recorder/login" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "secret",
    "company_subdomain": "itsworkplace",
    "device_id": "DESKTOP-ABC123",
    "platform": "windows"
  }'

# 2. Clock in (use token from login response)
curl -X POST "{{BASE_URL}}/api/recorder/time-tracking/time-in" \
  -H "Authorization: Bearer rec_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{"date":"2026-06-17","time":"09:00:00"}'

# 3. Check status
curl "{{BASE_URL}}/api/recorder/time-tracking/status" \
  -H "Authorization: Bearer rec_your_token_here"
const login = await fetch("{{BASE_URL}}/api/recorder/login", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    email: "user@example.com",
    password: "secret",
    company_subdomain: "itsworkplace",
    device_id: "DESKTOP-ABC123",
    platform: "windows",
  }),
});
const { token } = await login.json();

await fetch("{{BASE_URL}}/api/recorder/time-tracking/time-in", {
  method: "POST",
  headers: { Authorization: `Bearer ${token}`, "Content-Type": "application/json" },
  body: JSON.stringify({ date: "2026-06-17", time: "09:00:00" }),
});

Core Concepts — MCP Tools & Responses

MCP Tools

Named operations (e.g. get_clients, create_deal) invoked via tools/call. Live input schemas are returned by tools/list.

JSON-RPC methods

MethodPurpose
initializeHandshake; returns protocol version and server info
tools/listList all tools with inputSchema
tools/callExecute a tool by name
pingHealth check
notifications/initializedClient notification — returns HTTP 202, no body

Three layers of errors

LayerHTTPWhere to look
Transport auth401{"error":"Unauthorized","message":"..."}
JSON-RPC protocol200envelope.error.code (-32700, -32601, -32603)
Tool business logic200envelope.result.isError + parse content[0].text

Batch requests

Send a JSON array of JSON-RPC messages in one POST. Responses are returned as an array (notifications filtered out).

Parsing content[0].text

MCP tool results wrap the actual payload as a JSON string inside result.content[0].text. You must parse it.

{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\"clients\":[{\"id\":1,\"name\":\"Acme Inc\",\"email\":\"ops@acme.com\",\"status\":\"active\"}]}"
      }
    ],
    "isError": false
  }
}

Parsing checklist

  1. Check HTTP status — 401 means invalid/missing API key.
  2. Check envelope.error for JSON-RPC protocol errors.
  3. Check envelope.result.isError for tool-level failures.
  4. JSON.parse(envelope.result.content[0].text) to get the payload.
  5. If payload contains "error", handle the business error.
💡

Validation failures inside MCP tools return HTTP 200 with isError: false and text containing {"error":"Validation failed","details":{...}} — not HTTP 422.

  -H "X-API-Key: mcp_your_key_here" \
  -d '{ "jsonrpc": "2.0", "id": 2, "method": "tools/list" }'

Error Handling

ItsWorkPlace uses two error models. MCP tool errors often return HTTP 200.

HTTP status codes

200Success. MCP tool errors may also use 200 with isError: true.
202MCP notification accepted — empty body.
400Bad request — e.g. clock-in while already active, clock-out without clock-in.
401Missing or invalid API key or Bearer token.
403Account not active (Recorder login).
404Resource not found — company subdomain, upload session, recording file.
422Recorder validation failed — check errors object. (Not used for MCP tool validation.)
429Rate limited — planned, not yet enforced.
500Server error. MCP may return JSON-RPC -32603 internal error.

JSON-RPC error codes (MCP)

CodeMeaning
-32700Parse error — invalid JSON body
-32601Method not found
-32603Internal server error

MCP auth error (401)

{ "error": "Unauthorized", "message": "Missing X-API-Key header" }

Recorder validation error (422)

{
  "message": "The platform field is required.",
  "errors": {
    "platform": ["The platform field is required."]
  }
}

Rate Limits

⚠

Rate limiting is not currently enforced on MCP or Recorder routes. The limits below are recommended for a future release.

When implemented, respect the Retry-After header and use exponential backoff.

FAQ

What is the difference between the MCP and Recorder APIs?
MCP is JSON-RPC for CRM data integrations and AI agents. Recorder is REST for desktop/mobile time tracking and screen recording uploads.
Do I need a subdomain in the URL for MCP?
No. MCP resolves company scope from your API key, not the hostname.
Why is my tool response a string inside content[0].text?
MCP returns tool output as text content blocks. The text field is a JSON string you must parse with JSON.parse() or json_decode().
Why did I get HTTP 200 but isError: true?
MCP tool-level errors (permissions, not found, read-only key) use HTTP 200 with isError: true. Check envelope.result.isError before parsing the text payload.
How do I get write access?
Create a key with --write or enable write access in Admin → API Keys.
Can I limit which tools a key can call?
Yes. Set allowed_tools in the admin UI or use --tools=get_clients,get_deals with the Artisan command.
How long do Recorder tokens last?
30 days from issuance. There is no refresh endpoint — call login again.
What platforms does the Recorder API support?
windows and ios (required at login).
What file types can I upload for recordings?
webm, mp4, ogg, and mov — maximum 300 MB per file.
What timezone is used for clock-in?
The company timezone returned in the login response.
Can I use this with Claude Desktop?
Yes. Configure the MCP server URL and X-API-Key header in your MCP client.
Are batch JSON-RPC requests supported?
Yes. Send a JSON array of requests in one POST body.
How do I revoke an API key?
Delete it in Admin → API Keys. Effect is immediate.
Why is MCP validation not HTTP 422?
Validation runs inside tools. Failures return HTTP 200 with a JSON string containing error and details fields.
Is there rate limiting?
Not yet. It is planned — see the Rate Limits section.
Where is the live tool schema?
Call tools/list — it is always authoritative.
Do referenced IDs need to be in my company?
Yes. Cross-company references are rejected.
Where is the OpenAPI specification?
openapi.yaml — import into Postman, Stoplight, or Scalar.
What happens when I send notifications/initialized?
The server returns HTTP 202 with an empty body.
Can read-only keys call tools/list?
Yes. tools/list, initialize, and ping work with any valid key.
